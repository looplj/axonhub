## Required follow-up subrow candidates

### Tool families

- Responses `tools[]`: `function`, `custom`, hosted web/file/computer/code/image tools, `tool_search`, `mcp`, `namespace`, `apply_patch`, `local_shell`, `unknown_future`.
- Chat `tools[]`: `function`, `custom`, `unknown_future`.
- Anthropic `tools[]`: client tool, server tools, `mcp_toolset`, `unknown_future`.
- Deprecated Chat compatibility: `functions[]`, request `function_call`, response `message.function_call`.

### Tool choice variants

- Responses `tool_choice`: string values; typed object variants by target tool family; unknown future object variants.
- Chat `tool_choice`: string values; object forms; relation to deprecated `function_call`.
- Anthropic `tool_choice`: all official object/string variants; any parallel-tool-use control fields if present.

### Call lifecycle structures

- Responses: `function_call` → `function_call_output`; `custom_tool_call` → `custom_tool_call_output`; `tool_search_call` → `tool_search_output`; MCP list/approval/call/result item families.
- Chat: assistant `tool_calls[]` → tool role message; deprecated assistant `function_call`; streaming delta variants.
- Anthropic: assistant `tool_use` content block → later user `tool_result`; MCP `mcp_tool_use` / `mcp_tool_result`; streaming deltas.

### MCP / namespace / Codex-only behavior

- OpenAI Responses public MCP tool family versus Anthropic `mcp_servers` + `mcp_toolset`; keep separate until exact schemas are listed.
- Anthropic MCP companion: `mcp_servers[]`, `tools[].type = "mcp_toolset"`, `mcp_server_name`, `default_config`, `configs`, deprecated `tool_configuration`, response content types, batch behavior.
- Codex-only namespace rows: Responses `type="namespace"` parent tool, nested child tools, `custom_tool_call.namespace`, MCP `callable_namespace`, `mcp__` prefix, `codex_apps` namespaces, sub-agent namespace config, code-mode namespace filtering.

### Glossary / decision notes

- **Function tool**: A client-defined callable with a name and JSON input schema. It is the only tool family in this batch with strong common-abstraction potential across Responses, Chat, and Anthropic.
- **Hosted tool**: A provider-executed tool declared in the request, such as Responses web search, image generation, file search, code interpreter, or computer-use families. Hosted tools must not be flattened into function tools without explicit bridge code.
- **Raw-only tool**: A tool whose bytes/options are preserved in an adapter-specific raw sidecar rather than fully modeled in `llm.Tool`. Same-protocol roundtrip may be supported even when cross-protocol semantic conversion is unsupported.
- **Namespace tool**: A Responses tool schema for grouping tools under a namespace. Public Responses namespace evidence is P0; Codex runtime namespace conventions are P1 and must be documented separately.
- **Codex P1 behavior**: Behavior proven by Codex source/tests or fixtures, such as namespaced custom calls, sub-agent tools, or app namespaces. It is not an OpenAI public protocol guarantee.
- **MCP connector**: Anthropic `mcp_servers` plus `mcp_toolset` request machinery. It is not equivalent to the OpenAI Responses `mcp` tool object.
- **MCP tool in Responses**: An OpenAI Responses tool variant named `mcp`; treat as OpenAI adapter-specific/raw-preserve unless an explicit connector bridge is implemented.
- **Tool choice**: Request-side model guidance about whether or which tool to call. Basic string choices may overlap; named hosted/custom/native choices are protocol-specific.
- **Parallel tool call control**: OpenAI uses `parallel_tool_calls`; Anthropic uses an inverse nested flag `disable_parallel_tool_use` inside tool choice. Omitted/default must remain distinct from explicit false.
- **Tool-call lifecycle**: The sequence from model-emitted call to client or server-provided result. Definitions, call items, result messages, and stream deltas are separate row families.
- **Deprecated compatibility row**: A row for old Chat `functions` / `function_call` fields. These rows should not be merged with modern Chat `tools` / `tool_calls`.
- **Lossy flattening**: Converting a richer source structure, such as Responses namespace children, into flat Chat or Anthropic function tools. This may preserve callable names/schemas but loses grouping and provider-native semantics.
- **Unknown policy rule**: Unknown/future values require per-protocol and per-location evidence. Responses raw sidecar preservation does not imply Chat or Anthropic raw preservation.
