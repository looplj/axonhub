### Glossary / decision notes

- **Token-limit bridge**: the implementation path that maps Responses `max_output_tokens`, Chat `max_completion_tokens`, Chat deprecated `max_tokens`, and Anthropic `max_tokens` through `llm.Request.MaxCompletionTokens` and/or `llm.Request.MaxTokens`. This bridge is not value-identical across protocols and must carry precedence/default caveats.
- **Current token field**: Chat `max_completion_tokens`. It is distinct from deprecated Chat `max_tokens` and should not be collapsed into one matrix row.
- **Deprecated compatibility token field**: Chat `max_tokens`. It remains represented in AxonHub, but matrix text must identify it as compatibility-only and note target-specific precedence.
- **Anthropic default injection**: current Anthropic outbound behavior that emits `max_tokens=8192` when neither `MaxTokens` nor `MaxCompletionTokens` is set. Treat as implementation behavior requiring fixture evidence, not as a protocol default.
- **Server-side continuation**: Responses `previous_response_id` and `conversation`. These refer to provider-managed state and are not equivalent to Chat/Anthropic message arrays.
- **Raw top-level preserve**: same-protocol replay mechanism using `ProviderExtensions.OpenAIResponses.Request.RawTopLevelFields`. It can preserve fields not actively modeled in `responses.Request`, but it is not typed validation.
- **Prompt template reference**: Responses `prompt` object. It is not equivalent to Chat prompt text or Anthropic system prompt.
- **OpenAI prompt cache key**: `prompt_cache_key`, a cache routing key supported by OpenAI APIs. It is not equivalent to Anthropic `cache_control` blocks.
- **Prompt cache retention**: OpenAI retention policy field with values currently evidenced as `in_memory` and `24h`. Keep separate from `prompt_cache_key` and from Anthropic cache-control concepts.
- **Context management name collision**: Responses `context_management` and Anthropic `context_management` are not automatically equivalent. Same name does not imply bridgeability.
- **Implementation-gap row**: a field confirmed by official source but missing an AxonHub storage/restore seam. Chat `prompt_cache_retention`, Anthropic `container`, and Anthropic `inference_geo` are current examples in this draft.
- **Intentional unsupported direction**: a matrix direction where the target protocol lacks an equivalent field. The correct outcome is explicit loss/unsupported documentation, not inventing a mapping.
