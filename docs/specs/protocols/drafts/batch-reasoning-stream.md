### Round 2 field classification adjustments discovered

1. Responses stream classification needs a new reasoning-specific stream event subfamily. 5. Anthropic stream classification remains named SSE event families plus nested `content_block_delta.delta.type` variants; no category move is needed, but unknown future event handling is explicitly P0-confirmed by Anthropic versioning text.

### Round 3 lossiness notes by risk type

- Semantic loss:
  - Responses `reasoning.context` is official P0 but absent from current `responses.Reasoning` struct.
  - Anthropic `thinking.display`, `adaptive`, and `disabled` are preserved through metadata only for Anthropic-aware paths and have no official Chat equivalent.
  - Responses encrypted reasoning and Anthropic signatures/redacted thinking are both opaque continuity artifacts, but they are not proven equivalent.
- Default-value loss:
  - Responses/Chat model-specific reasoning effort defaults are not represented in code; code stores only explicit strings.
  - Anthropic adaptive default/budget behavior is approximated in code by setting common `ReasoningEffort` to `high` on inbound.
  - Anthropic outbound may generate a placeholder signature when closing a thinking block without one.
- Range/value loss:
  - Anthropic `budget_tokens` is numeric and maps to coarse effort buckets for non-Anthropic targets.
  - OpenAI effort enums include values that may not map one-to-one to Anthropic budgets or Chat model support.
- Stream-shape loss:
  - Responses semantic events have more structure than Chat chunks; conversion loses event names/sequence numbers/index detail in many paths.
  - Anthropic ping/content_block_stop/unknown events are skipped on Anthropic outbound-to-common stream conversion.
  - Chat `[DONE]` is a sentinel, not a JSON event, and has no exact Responses/Anthropic event object equivalent.
- Unknown-value risk:
  - Responses top-level unknown fields have raw-preserve sidecar, but unknown nested fields inside known `reasoning` are not shown as raw-preserved by P2 evidence.
  - Anthropic unknown future SSE events are P0-allowed by versioning guidance, but current filter skips unknown event types.

### Round 4 merge guidance

- Split request-level controls from response reasoning content and stream reasoning events. Do not merge `reasoning_effort`, `thinking.budget_tokens`, and reasoning-token usage into one row.
- Treat `effort` and `budget_tokens` as different field classes: effort is an enum/control level; Anthropic budget is a numeric token allocation that counts toward `max_tokens`.
- Treat hidden continuity artifacts separately: Responses `encrypted_content`, Anthropic `signature`, Anthropic `redacted_thinking.data`, and Chat absence of an official signature field.
- Treat stream event families as protocol-native event models, not as request fields. Cross-protocol stream rows should be lossy structural transforms unless a subrow has explicit lossless evidence.
- For final matrix drafting, use `Ready for matrix draft` rows as initial candidates, but do not assign final status until tests/samples are attached by the main session.

### Glossary / decision notes

| Term / rule | Durable meaning for this batch |
|---|---|
| Request reasoning / thinking control | Request-side knobs that guide model reasoning behavior, such as Responses `reasoning.*`, Chat `reasoning_effort`, and Anthropic `thinking.*`. These are not response content. |
| Response reasoning content | Provider-returned reasoning material such as Responses reasoning items or Anthropic `thinking` blocks. Keep separate from request knobs. |
| Hidden continuity artifact | Opaque provider material used for continuation/integrity, including Responses `encrypted_content`, Anthropic `signature`, and Anthropic `redacted_thinking.data`. Preserve when possible, but do not translate as visible text. |
| Effort | OpenAI-style enum/control level (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`). Effort is not a token count. |
| Budget tokens | Anthropic numeric token allocation for extended thinking. `budget_tokens` is not equivalent to OpenAI effort and must not be converted as if it were the same field. |
| Reasoning-token usage | Usage accounting for consumed/generated reasoning tokens, such as Chat/Responses reasoning token counts. Usage tokens are not request effort and not Anthropic thinking budget. |
| Summary control vs summary content | Responses `reasoning.summary` is a request control. Responses reasoning item `summary[]` is response content. They require separate matrix rows. |
| Encrypted vs redacted vs signature | Responses encrypted content, Anthropic redacted thinking, and Anthropic signature are all opaque/hidden artifacts, but their semantics are provider-specific. Treat cross-protocol conversion as lossy/unsupported unless a source proves equivalence. |
| Stream option | Request-side streaming configuration, for example Chat `stream_options.include_usage` or Responses `stream_options.include_obfuscation`. A stream option is not a stream event. |
| Stream event | Wire-level event/chunk emitted during streaming, such as Responses typed SSE events, Chat completion chunks and `[DONE]`, or Anthropic named SSE events. Event families need subrows because variants carry different payloads. |
| `[DONE]` sentinel | Chat streaming frame terminator. It is protocol framing and should not be modeled as assistant content. |
| Unknown future event | A stream event not recognized by the current implementation. Main matrix should record the chosen behavior: raw-preserve, diagnostic, skip/no-op, or reject. |
| Same-protocol replay | A request/response parsed from one protocol and emitted back to the same protocol. This is where raw-preserve/deprecated-spelling issues matter most. |
| Cross-protocol conversion | Conversion between different protocol families. For this batch, stream event shape and hidden reasoning artifacts are usually lossy unless a specific subrow proves otherwise. |
