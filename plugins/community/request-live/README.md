# 实时请求

侧栏页面插件。四列从左到右是：

**客户端 → API 密钥 → AxonHub → 渠道**

每一列只回答一件事：请求从哪个客户端来、用了哪把 API 密钥、经过 AxonHub、最后实际打到哪个渠道。页面不画路由过程，不解释为什么选了这个渠道，也不展示请求或响应正文、请求头、流式分片、上游 URL、用量或配额。

## 概览与轨道

页面默认不选中任何请求，直接显示进行中请求的概览。每个 `pending`/`processing` 请求按 request id 拥有一条独立轨道，最多同时显示 10 条；同一客户端、同一密钥、同一渠道上的多个并发请求也会各自成轨，不会合并成一条完整路径。进行中轨道用虚线流动表示，颜色按 request id 的稳定哈希分配，跨轮询不变；红色只用于失败或取消。超过 10 条时页面显示明确的 `+N` 数量，被选中的请求如果本来落在溢出范围内，会自动拉回可见轨道。

轨道通过垂直偏移、轨道编号和渠道卡片上的编号圆点区分。即使多条请求完全同路，它们的路径也不会完全重合。选中的轨道会加粗，其余轨道淡化；下方请求列表仍然显示全部请求。

点击轨道、渠道卡片上的编号圆点或列表行可以选中请求。再次点击同一项、按 Esc，或点「回到实时」都会清除选中。选中的请求不会因为新请求到达而被替换。进行中请求完成后停止流动，保留约 3 秒再淡出；失败和取消同样保留并显示红色。页面没有进行中请求时，会显示最近历史请求的静态概览，而不是退回成单一焦点。

执行记录只取每个请求最新的 8 次 attempt，并读取 `totalCount` 用于显示第几次执行，因此超过 8 次重试时仍能看到最终执行和最终渠道。客户端、密钥、渠道列有软上限（6/8/12），超出时在列标题显示 `+N`；轨道和选中请求所需的节点始终保留。

客户端靠 `Request.userAgent` 识别。产品名是 User-Agent 里第一个 `/` 或空格之前的词。已知客户端（Claude Code、Codex、Cursor 等）按别名和前缀匹配。`source` 为 `playground` 时一律算作 Playground，避免管理台浏览器被显示成 Chrome。空 User-Agent 且来源是 `test` 时显示为 Test，其余显示为未知客户端。

数据只来自插件 GraphQL 的轮询，没有订阅。时间窗可选近 5/10/15/30 分钟、近 1/2 小时或今天，默认 15 分钟；条数可选 25/50/100/200，默认 50；刷新间隔可选 2/5/10/20/30/60 秒，默认 2 秒。页面隐藏时暂停轮询，重新可见时立刻刷新一次。

进行中的请求（`pending`/`processing`）单独查询，不占用历史条数，并用 cursor 分页，每页 200 条、总预算 1000 条；分页只读 `edges` 和 `pageInfo`，不逐页取总数。精确总数复用独立统计；统计尚未到达时显示“已加载 N 条，仍有更多”，轨道溢出按已加载数量标为下界，不伪造精确总数。历史列表按所选时间窗和条数两个条件取最新 N 条，两者合并时按 request id 去重，所以跨窗口开始的长请求不会被最新 N 条挤掉。

上一轮还可见、这一轮已经从列表消失的进行中请求，会按 request id 补查有限数量的终态（可见轨道加选中项）。只有明确返回 `pending`/`processing` 才继续作为活跃请求；节点明确返回 null 时直接退出活跃跟踪。网络或权限失败时请求标记为状态未知（stale）、停止活跃动画，并在 60 秒 TTL 内继续有限补查；超过 TTL 后移除，不会永久显示为 processing。返回 completed/failed/canceled 时保留约 3 秒轨道，即使它已经落在历史创建时间窗口之外；补查到的最终 attempt 和渠道会通过 executions 合并回这条 linger 轨道。

带渠道对象的查询如果遇到一般 FORBIDDEN，会最多重试一次只选 `channelID` 的查询；只有重试成功才降级为只显示渠道 ID。重试仍失败时按正常错误显示，不把渠道降级当成事实。所有请求查询始终保留 `channelID`。

统计（窗口请求数、当前进行中、窗口失败数）是独立请求，不阻塞列表；查询使用合法的 `first: 1` 并且只读取 `totalCount`。统计最多每 10 秒刷新一次，节流是全局的，切换时间窗不会清零；新窗口在剩余节流结束后才查询。统计响应有自己的序号和窗口版本，慢响应不会被后续列表轮次丢弃，但旧统计不能覆盖新统计。统计自己记录所属时间窗，不依赖列表的取数状态；切窗后列表失败而新窗口统计成功时仍会显示。统计或列表任一失败时，另一部分仍会显示；列表首次失败时，成功的统计仍然可见。

页面上的数字区分口径：窗口共 N 条来自独立统计；列表最新 N 条是实际取回的历史页；当前进行中是全部 `pending`/`processing` 的数量。选择客户端筛选后，三项数字改为当前列表样本的统计，并标注样本来源。

## 权限

安装时需要授予：

- `read_requests`：读取请求和执行记录
- `read_api_keys`：读取 API 密钥名称和状态
- `read_channels`：读取渠道名称

没有 `read_channels` 时，列表会改用不含渠道对象的查询，渠道列只显示渠道 ID，并给出一行权限提示。

## 打包

按 [插件目录说明](../../README.md) 安装打包器，然后在 AxonHub 仓库根目录运行：

```sh
pack-plugin plugins/community/request-live -o /tmp/request-live.axplugin
```

在 AxonHub 的 PR 中递增 `manifest.json` 版本。合并到 `unstable` 后，AxonHub 向 [axonhub-plugins](https://github.com/looplj/axonhub-plugins) 发送事件，由那边检出这个提交并打包发布。

## 安装

用 Owner 账号在「插件」页上传 `.axplugin` 插件包，勾选上面的三项权限后启用。侧栏入口是「实时请求」，地址是 `/plugins/local.request-live/pages/live`。
