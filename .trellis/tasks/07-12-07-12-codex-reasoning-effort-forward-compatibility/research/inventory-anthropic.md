## Evidence method and boundaries

1. Field IDs and current status come from `docs/specs/protocols/protocol-conversion-strict-verification-matrix.md` §5.3, §6, §9, §11, and §14.4.
2. Ownership and preservation rules come from `.trellis/spec/backend/protocol-transformer-guidelines.md`: Anthropic-native fields belong in the Anthropic adapter; same-protocol fidelity comes first; incompatible cross-protocol fields must not be fake-mapped.
3. Protocol shape/value evidence comes from `docs/specs/protocols/anthropic-claude-messages-protocol.md` and the three routed batch drafts. The baseline explicitly requires raw preservation for unknown content-block types and identifies detailed usage/stop fields as preservation targets.
4. Source discovery used `/Users/asuan/.local/bin/codebase-memory-mcp cli ...` against ready index `Users-asuan-AI-axonhub-llm`. Conclusions below use actual source returned by `get_code_snippet` or live `search_code`; `rg` was limited to Markdown, fixtures, test names, and literal field/event strings.
5. The matrix currently has aggregate IDs only for several requested children: there is no registered standalone ID for request `context_management`, response `usage`, response `stop_details`, or individual server-tool variants. Those are recorded below under the nearest existing aggregate row and explicitly marked as an ID/documentation gap; no new authoritative Field ID is invented here.
6. Classification is about the **next observable work item**, not aggregate completion. `IMPLEMENTATION` requires a source assignment/switch/model that directly proves loss; a stale `UNCHECKED` matrix cell alone is not enough.

## Final classification summary

### Proven `IMPLEMENTATION` findings

- Unknown/future request content blocks, including unhandled request `search_result` shapes, are not carried from `MessageContent.Raw` into canonical/sidecar state.
- Unknown/provider-native children inside `tool_result.content[]` are dropped by the closed nested switch.
- Anthropic-only optional children on ordinary function-tool declarations are absent from the wire model and have no raw replay.
- Native/server tool declarations other than web search and `mcp_toolset` are explicitly ignored.
- Unknown future Anthropic SSE events are filtered out; the observable drop is proven, while the exact raw-replay/diagnostic policy remains to be chosen.
- The matched response `stop_sequence` string is not preserved.
- Response `stop_details` is not modeled or sidecar-preserved.
- Server-tool/future response usage details are not modeled or raw-preserved.
