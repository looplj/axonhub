# OpenAI Responses output / runtime-stream protocol gap inventory (read-only round 1)

- Date: 2026-07-13
- Scope: `RSP.RESP.*`, `RSP.STREAM.*`, response `output[]`, response lifecycle/status/error/incomplete/usage/annotations, runtime SSE parser/aggregator/emitter.
- Explicitly excluded: request `stream_options` (G14, already completed), request `input[]` identity (G15), production changes, fixtures, strict matrix, and existing specs.
- Classification rule: **IMPLEMENTATION** only where the checked-in protocol baseline plus current source/fixture proves a value/event is discarded or cannot be re-emitted. Absence of a named test alone is **TEST_ONLY**. A protocol family with no valid cross-protocol representation is not automatically `EXPLICIT_NO_IMPLEMENT`; same-Responses fidelity remains the primary seam.

**Observable public paths audited**

1. Non-stream same-family: provider Responses JSON → `OutboundTransformer.TransformResponse` → `llm.Response` → `InboundTransformer.TransformResponse` → client Responses JSON.
2. Stream same-family: provider Responses SSE → outbound `TransformStream` → common stream → inbound `TransformStream` → client Responses SSE.
3. Aggregation: captured provider SSE chunks → `AggregateStreamChunks` → final Responses JSON / usage metadata.

The current design is semantic reconstruction, not byte/event passthrough. Therefore a supported event may legitimately receive a new sequence number, but an official item/event payload that disappears entirely is an observable loss.

## C. Classification summary

### Confirmed implementation gaps

1. Non-stream response status loses `queued` and `in_progress` by defaulting replay to `completed`.
2. Non-stream response loses `incomplete_details`.
3. Message `refusal` output content is ignored.
4. Official output item families without a response carrier are discarded: file search, computer, code interpreter, MCP call/list/approval, tool-search call/output, local/shell/apply-patch (each must be fixture-split and baseline-shaped before implementation).
5. Runtime `response.queued` is declared but ignored.
6. Checked-in canonical runtime event families absent from current parser/emitter/aggregator: audio, audio transcript, code-interpreter progress/code, and compaction.
7. Stream aggregator ignores a valid top-level `error` event.

### Test/documentation gaps only

- Supported envelope, lifecycle, text, function/custom tool, reasoning G7, image final content, annotations, usage, previous response id, service tier, error type/code/message.
- Mixed output ordering and per-event lifecycle invariants need narrow public fixtures.
- Original SSE sequence numbers and part/progress event identity are not claimed as preservation requirements; test semantic ordering instead.

### Explicit no-implementation boundaries

- Request `stream_options` is G14 and is not a runtime event.
- Codex app-event/turn lifecycle, approvals, sandbox, OAuth, multi-agent, and telemetry are not Responses SSE events.
- Do not bridge native Responses MCP/output items to Anthropic MCP configuration or client control-plane behavior.
- No Codex-specific item-id prefix or model capability policy belongs in response/stream conversion.

## D. Recommended RED slicing order (no changes made in this round)

1. Envelope: `status queued/in_progress`, then `incomplete_details`.

3. Aggregator: top-level error.
4. Runtime absent events, one event family per fixture: queued; audio; transcript; code-interpreter phase; code delta/done; compaction.
5. Output items, one family per fixture, using exact local snapshot unions; never one broad “all tools” fixture.
6. Supported-family confidence fixtures: mixed order, lifecycle ordering, terminal usage precedence, annotation subtype table.
