## Classification legend

| Classification | Meaning in this inventory |
|---|---|
| `IMPLEMENTATION` | Current observable mapping is wrong/unsafe and needs a production policy or conversion change. |
| `TEST_ONLY` | A source-to-canonical-to-target path exists; the remaining gap is a targeted public-seam fixture/assertion. |
| `DIAGNOSTIC` | Intentional/no-equivalent cross-protocol loss is currently silent or lacks field-specific `LossyDowngrade` proof. |
| `DOC_ONLY` | Code behavior exists, but matrix/FDR/default/null/value-domain documentation is incomplete or stale. |
| `EXPLICIT_NO_IMPLEMENT` | No bridge should be created; preserve only the documented native/same-family behavior. |

A row may carry more than one classification when, for example, same-family behavior only needs a test but a cross-family loss needs a diagnostic.

## Prioritized verified gaps

1. **Production/value-policy gap (`IMPLEMENTATION`)**: OpenAI `temperature` values above Anthropic's allowed range are blindly emitted to Anthropic; cross-protocol `service_tier` strings are blindly emitted despite incompatible vocabularies.
2. **Field-level diagnostic gaps (`DIAGNOSTIC`)**: penalties, seed, stop/stop_sequences to Responses, arbitrary OpenAI metadata remainder to Anthropic, safety identifier, and prompt cache key/Responses retention can disappear without a field-specific `LossyDowngrade`.
3. **Test-only matrix backlog (`TEST_ONLY`)**: model, request `stream`, top_p, token-limit precedence, metadata identity, and stop structural mapping already have code paths but lack focused public six-direction/presence fixtures.
4. **Documentation/blocked semantics (`DOC_ONLY`)**: official null/default behavior, Anthropic top_p range, model omission semantics, provider-extension applicability for `top_k`, and exact service-tier value maps remain unverified. No cross-protocol mapping should be invented for these.
